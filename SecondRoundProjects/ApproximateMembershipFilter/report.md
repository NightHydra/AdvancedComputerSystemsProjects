## Introduction

In this report, we aim to quantify the performance of different approximate membership
filters when variables such as the target false positive rate (FPR) and hash size are varied.
The four filters implemented for this project are the xor filter,
cuckoo filter, quotient filter and blocked bloom filter.  Each filter was
implemented using defines so that access would be as small as possible.

## Methodologies

For this experiment, each test is conducted 100 times and the p95 tail latency is used
for all throughput calculations when plotting.  This is done since for membership tests,
we really care about the worse case scenario.  This also means that the p95 tail FPR is used
for the FPR plots as well.

## FPR Sweep

The plots generated by the tests conducted plot the target false positive rate
vs the actual false positive rate.  An additional plot is generated showing throughput vs
the target FPR.


## Load Factor Sweep

Again, the plots generated show how the load factor effects the actual false positive rate and the
lookup times for whether and element is in the structure.

## Varying Workload

The plots again show how performance and actual FPR vary when changing the workload ratio.
When generating this plot the number of queries vs inserts were varied for each test run.
Two other plots show data sweeping the negative lookup share from 0%-60% to 90% and how the negative
loopup ratio impacts performance.

## Thread Scaling

For testing how varying the thread count impacts the performance metric
I kept other parameters constant while varying the number of threads from 1-2-4-8 threads.

As seen by the plot showing perfomance with varying threads, the false positive rate does not change.
This makes sense as the algorithm is the same and should not be effected by the number of threads being used 
to perform the operation.  However, we can see that multithreading does not offer major performance increases
especially for small test-sets.  This makes sense as there is obviously the overhead needed to just start and manage
all of the threads.  Additionally, the problem of the total time being the time of the worst thread also impacts
the performance.
